## B 學習目的與範圍

### B1 核心問題

同一次晶片交付中，實物被送到哪裡、誰替誰完成工作，以及規格與結果傳給誰，為什麼是三種相互配合、但不等同的關係？

### B2 三項可觀察目標

| ID | 看完應能理解 | 觀眾應從畫面看到什麼 |
| --- | --- | --- |
| L1 | 物料／實物與資訊的傳遞規則不同。 | 批次 A 離開代工廠後原地不再有另一份 A；規格送出後設計公司仍保留原件；報告回傳時晶片仍在封測廠。 |
| L2 | 服務回答「誰替誰完成什麼工作」，委託單與報告則是相關資訊。 | 封測廠內實際發生封裝與測試；固定服務關係連向設計公司；服務線上沒有小球或貨物行駛。 |
| L3 | 同一家公司可以同時參與三種關係；委託方、加工方與指定收貨方不必是同一角色。 | 同一封測廠收晶圓、執行受託工作、回傳報告，再把成品送到系統廠；報告與成品終點不同。 |

起點：
- 已加工的矽晶圓批次 A 位於晶圓代工廠出貨端。
- 本例所需的前置晶圓判定、晶粒選用資料、製程與測試方案已備妥；不在本片重新開發它們。
- 設計公司與封測廠已約定合作及服務條件，本批作業資料尚未送達。
- 封測廠已備妥本批封裝材料，系統廠是本例指定的成品收貨方。

終點：
- 同一追蹤批次的可交付成品在系統廠。
- 測試報告在封測廠與設計公司各保留一份。
- 封測工作已完成，服務關係仍可見；物料沒有繞回設計公司。

前置知識：
- 不要求理解半導體元件物理。
- 收合說明用一句話解釋：晶圓上有許多晶粒；封裝為晶粒提供連接與保護；測試依指定條件取得結果。
- 主畫面可用「設計公司／委託方」「晶圓代工廠」「封測廠」「系統廠／收貨方」短標籤。Fabless、OSAT 的英文全稱只放說明區。

本次不展開：
- 晶圓製造的詳細步驟、封裝剖面、晶圓級封裝與先進封裝。
- 採購付款、價格、所有權、稅務、運輸承攬契約與地理距離。
- 設計 IP、EDA、設備維護、退貨、不良分流與完整供應鏈風險。
- 委託者也可能是 IDM、代工廠或其他角色；本次只演示一個設計公司委外的安排。

最多三個後續子題，僅列出，不實作：
1. 同一實物流路徑，為什麼可能有不同訂單與貨權安排？
2. 規格變更或測試異常，如何造成等待、重測或改期？
3. 設備商的設備交付、維修服務與製程資料如何交會？

### B3 收合區中的理解檢查

以下三題附短答，預設收合；不設答題門檻。

Q1：本例誰委託封測、誰執行、誰收到成品？
A1：設計公司委託，封測廠執行，指定系統廠收貨。這是本例安排，並非所有供應鏈都如此。

Q2：委託資料與測試報告都是「服務」嗎？
A2：它們是資訊。受託執行封裝與測試是服務活動；資訊用來說明要求、記錄結果與協調交付。提供服務也可以同時交付加工後的實物。

Q3：報告回到設計公司，晶片也一定回去了嗎？
A3：沒有。畫面中報告傳送時晶片留在封測廠；之後才依本例出貨指示送到系統廠。資訊副本不等於另一批晶片。

### C2 本題採用的分析定義

- 物料／實物：本片追蹤的可被搬運、存放或加工的晶圓、封裝材料與成品。為便於初學者理解，主圖的「實物」涵蓋原材料、在製品與成品，不把成品排除在外。
- 服務：一方依約替另一方執行工作。本片服務是封裝與測試；它可以改變實物，也可以產生測試資料。服務不能只用一張委託單代替。
- 資訊：本片的作業要求、測試結果與出貨指示。文件圖示代表電子資料內容，不是紙張在公路上運送。
- 三者是分析「關係、活動與交付內容」的角度，不是三種互斥的公司，也不要求每一事件只能歸一類。
- 傳遞資訊本身也可能由業者提供為服務；本片在「資料內容」層次把報告歸入資訊，在「受託工作」層次把測試歸入服務。不要為了分類而否認兩者可同時存在。
- 實物箭頭只表示所在地變化，不表示買賣成交、所有權移轉、付款或法律責任轉移。

### C3 本次選定情境，不冒充產業普遍規則

M01：四方角色為 D 設計公司、F 晶圓代工廠、O 封測廠、C 系統廠。D 是本次封測委託方，C 是 D 指定的收貨方。

M02：本例實物路徑固定為 F → O → C。D 不作為物料中繼站。物流業者、倉庫和跨境運輸合併在兩段移交中。

M03：採矽基單晶粒 IC 的一般後段情境，將切割與封裝合併呈現，再展示封裝後的電性測試。不畫特定封裝型號或內部結構；不把此順序套用到所有封裝技術。前置晶圓測試與選片資訊已備妥，不表示產業只有封裝後才測試。

M04：D 先送本批封裝／測試作業資料；O 完成工作並回報；D 檢視後發出本例出貨指示；O 收到指示後送至 C。這個「報告先回、確認後出貨」是本題選定的協調規則，公開資料並未要求所有業者採相同時序。主畫面在出貨指示段顯示「本例：確認後出貨」。

M05：示範選取可交付的結果，不演出失敗、報廢、重測或退貨，不推論良率 100%。報告僅顯示「A／本例條件符合」，不填捏造的電壓、良率、測試件數或認證結果。

M06：封裝與測試工程、設備、介面、材料及必要資訊都已具備。畫面中的文件是本批作業資料的概括，不能理解成「收到一張紙就足以製造任何晶片」。

M07：A 是教學追蹤群組，連結其加工前後的來源，不保證實際生產的 lot 編號永不改變。圖示不表達晶圓數、晶粒數、成品數或一對一轉換比例。

### C4 必須保留的因果及不變條件

- O 在本批作業資料到達、實物入料之前，不執行本批封裝。
- 封裝有材料投入；測試新增的是紀錄與判定，不將晶片消耗成報告。
- 報告須在本次測試結束後出現，不能一開始就有「已測試」的結果。
- 本例的出貨指示須在 D 收到報告後產生；實物出貨須在 O 收到指示後開始。
- 同一追蹤批次在任一非重設時刻只有一個實物位置。加工遮罩遮住外觀時，批次仍存在。
- 資訊複本可在兩端並存，不能據此增加晶片。這是有授權端點間的示範，不宣稱資料可任意公開分享。
- 服務提供地點與關係端點不能隨實物出貨改變：工作在 O，受託服務對象是 D。

### C5 省略、數值與疑點

- 本題是定性的供應鏈關係示意，不是物理、排程、良率或離散事件產能模擬。
- 無需場量、微分方程、實測資料、粒子求解器或隨機數。
- 唯一數值時間是動畫秒數；空間尺寸是畫面配置。皆不對應實際工期、距離、速度、數量或產能。
- 封裝內部操作、材料損耗、不良品、批次分流、前段資料交換與其他合約省略；不得用虛構精確數據補齊。
- 真實資料、排程與物流可以並行；本片依序突出關係是教學安排，不宣稱必然串行。
- 未解決且阻礙實作的科學疑點：無。具體交易和出貨核准規則的非唯一性，已透過 M01–M07 明確限定。

## D 視覺表示、物件與狀態

### D1 圖像選型

採「同一組固定角色、三種關係共存」的二維關係圖。它能直接比較同一封測廠的實物、受託工作與資訊去向，且不把服務誤畫成第三種物流。

這不是地圖、廠區平面或電路圖。角色距離不表示地理距離，線條不表示電性導通。無需道路、車輛、人物、世界地圖或三維攝影機。

主要角色全程固定，不因目前強調的關係而換位置，也不複製成三張互不相干的圖。每段突出一個主要動作，其他角色和既有關係保持可辨識。

### D2 主畫面的必要文字

- 四個角色短標籤。
- 常駐三項圖例：「實物：移交」「資訊：傳送與保留」「服務：誰替誰做」。
- 當前階段一行短句，依 E1。
- 小字「委外封測案例・非實際工期」。
- 追蹤標記「批次 A」；報告、指示以「A」對應同批。
- 封測廠旁的「封裝材料／已備」或加工後的「已投入」。
- 播放、重播、速度、時間定位與說明入口。

不放大標語、宣傳式首頁、企業排名、密集資訊卡或長篇介紹。重要語義不能僅靠懸停看見。

### D4 布局與接點

桌面：
- F、O、C 形成左至右的實物主線；D 放 O 上方。
- D 與 O 間保留三條分離走廊：作業資料／出貨指示向 O；報告向 D；服務關係由 O 指向 D。
- 服務線不可與任一資訊線完全重疊，三類線各有獨立接點。
- O 的物料槽、文件槽、材料備料區與工作區分開，不能讓移動報告被誤認為來自晶片本體。
- 主圖中央優先留白，角色只需要必要的細框／括線，不做儀表板式大卡片。

窄螢幕：
- 使用第二套布局錨點，不把桌面 SVG 等比縮到字太小。
- 建議右列自上而下為 F、O、C；D 在 O 左側。
- 實物流走右列；D → O 的資訊從上側繞入，O → D 的報告從下側回傳；服務線在兩角色之間直接連接。
- 線路仍代表同一關係，轉向或換布局不改來源、去向與時間。
- 在 390 × 844 CSS px 中，面板關閉時四角色、主要動作、圖例與播放入口均可看見；不依賴水平捲動。
- 四角色的位置與線路端點可按可讀性微調，語義與接點分離不可改。角色文字以約 14–16 CSS px 為起點，不能因 SVG viewBox 被縮小而失去可讀性。

本題不需第二張獨立動畫或實體剖面。若說明需要對照，使用當前主圖與短文字，不另建會漂移的時鐘。

### E3 循環語義與接縫

選用「重新示範」，不採新一批，也不假裝是物理週期。

- 28–31 秒：結果停留。
- 31–31.35 秒：批次、材料、文件、夾具、工作狀態和階段強調整體淡出；四角色及不帶完成狀態的關係線保留。小字提示「重新示範同一案例」。
- 31.35–31.65 秒：上述動態內容完全不可見；固定在 31.5 秒切換至初始條件。31–31.5 秒沿用結果幀的內容，31.5–32 秒使用初始幀的內容，再套用此處規定的透明度。這是由時間推導的切換，不是等待播放事件才清空物件。此處無需讓晶圓逆向移動。
- 透明度、當前階段與「重新示範同一案例」提示仍依實際時間 t 決定，不跟著初始資料一起套用 0 秒的階段文字。
- 31.65–32 秒：初始晶圓、備料、規格與初始狀態淡入；32 秒與 0 秒外觀一致，重設提示消失。
- 追蹤 ID 仍為 A，不逐輪增加編號，不累加庫存或報告；這是同一範例重講。
- 手動重播直接回 0 秒並播放；手動定位可跳時，但不補播反向加工。
- 所有淡出與遮罩也由主時間決定。直接定位到重設區間，結果須與順播一致。
- 若時間控制器允許定位到恰好 32 秒，顯示完整初始幀並保持暫停；播放繼續時循環至 0 秒，不出現額外空白幀。

### E4 速度與空間插值

- 1 倍速為 32 秒，0.5 倍為 64 秒，1.5 倍約 21.33 秒，2 倍為 16 秒；都是播放時間，不是實際工期。
- 文件與批次移動可用平滑單調插值；路徑速度不代表物理速度。
- 段內可採 p = 3u² − 2u³，u 為該段正規化進度。這只是視覺緩動，不能標示成物理方程。
- 角色不移動，物件不閃現到新地點。文件在目的地的建立與傳輸圖示的消失必須在同一時刻銜接。
- 調速只改主時間前進率，不改當前物件位置、資料副本數、階段或路線。

## F 本題完整播放與介面規則

1. 一般情況開啟即以 1 倍速從 0 秒播放；全部主要動作由一個主時間控制。沒有聲音，也不需要外部影音資產。
2. 提供暫停／接續、重播、0.5／1／1.5／2 倍速、時間定位和 E2 關鍵步驟定位。速度變更保留相位；暫停中調速仍暫停；重播歸零並播放。
3. 時間軸開始拖曳或用鍵盤改值時先暫停，完成定位後保持暫停。每個中間時間都可獨立顯示，不必先看前面。
4. 開啟說明面板先暫停；關閉仍暫停；按播放收合面板並接續。切換面板中的說明小節不改時間；只有「定位此步」會跳到指定幀且保持暫停。
5. 背景分頁凍結主時間。返回時保持原本的播放或暫停意圖，不補算背景經過時間。離開前正在播則從原相位續播，離開前暫停則維持暫停。
6. 視窗縮放、裝置轉向及桌面／手機布局切換保留主時間、速度、播放意圖及目前資料狀態。
7. 系統 prefers-reduced-motion 開啟時，初始顯示 29 秒的有意義靜態總覽，不自動循環；顯示簡短提示「靜態總覽，播放將從頭示範」。
8. 上述靜態總覽的首次明確「播放」從 0 秒開始。使用者若先自行定位，則之後播放從其選定時間接續；重播一律從 0 秒。這是本題對減少動態初始狀態的明確例外。
9. 執行中系統偏好切為減少動態，立即暫停於當前時間，不跳回總覽。偏好恢復一般時也不自動播放，等使用者按播放。
10. 所有控制有可及名稱、鍵盤入口、可見焦點；實際點按區以至少 44 × 44 CSS px 為目標。速度選單、時間軸、說明面板均可用鍵盤操作。
11. 若面板以對話框呈現，開啟後焦點進入面板，Escape 可關閉，關閉後返回開啟按鈕；不能陷入無法退出的焦點區。播放按鈕關閉面板後仍保持合理焦點。
12. 圖像提供簡短文字替代與目前階段文字；不每幀朗讀座標或秒數。替代文字須說出「成品給系統廠，報告回設計公司，工作在封測廠」。
13. 同一時間及相同布局設定必須得到同一畫面。暫停時所有位移、線條高亮、遮罩與局部工作動作都停止；不能用獨立 CSS 動畫繼續跑。
14. 面板預設收合；關閉後恢復主圖完整可見。沒有必答測驗、帳號、排行榜或遊戲經營操作。
15. 本題不加入關係篩選器或三層切換作為必要操作；自動演示已足以區分三者，結尾需能同時比較。

## G 實作與重用範圍

### G1 最小技術選擇

- 主圖使用 Inline SVG：本題只有少量角色、線段、文件與批次圖示，SVG 適合清楚線型、可讀文字與響應式錨點。
- 使用單一 requestAnimationFrame 驅動主時間。若既有環境有合格時鐘，驗證後沿用；不要在各角色建立獨立 interval。
- 運用 Work 可用且實際能執行的網頁環境；不強制改框架。
- 不需要 Canvas 粒子、物理引擎、3D、後端、帳號、資料庫、流程編輯器、通用製程語言或完整供應鏈模擬器。
- 原創幾何即可，不需再搜尋 Mini Motorways 的圖片、地圖或介面。

### G2 邏輯分工

建議兩個最小責任邊界，以下是新實作建議，不是假稱已存在的 API：
- 主題狀態：輸入主時間 t，直接得到完整的角色內容、物件位置、文件副本、服務狀態、遮罩、路線強調與階段文字。
- 呈現：把完整狀態映射至目前桌面或手機的錨點；布局變更不改模型狀態。

共用部分僅包含時間、控制、面板及基本樣式；本題部分包含關係、物件、文案、時程與圖形。
總長、時間邊界、文案、路線、色彩和布局錨點集中可調。不要把「等待文件到達」做成不可回溯的事件回呼。

### G3 可直接推導的狀態規則

以下規則適用於正常可見區間 0 ≤ t < 31；31–32 依 E3 對整組內容統一套用重設狀態與透明度。

- lot_A：
  - 0 ≤ t < 7：F。
  - 7 ≤ t < 10：M_FO 上，路徑進度由 t 唯一決定。
  - 10 ≤ t < 25：O。
  - 25 ≤ t < 27.5：M_OC 上，路徑進度由 t 唯一決定。
  - 27.5 ≤ t < 31：C。
- lot_A 內部外觀：
  - t < 12：晶圓圖示，11–12 逐漸被遮罩遮住。
  - 12 ≤ t < 15：內部不可見，A 的追蹤框仍存在。
  - 15 ≤ t < 16：封裝件圖示逐漸露出。
  - t ≥ 16：封裝件托盤；測試不再改變其外形。
- mats_A：t < 11 已備；11–12 在 O 內加入；t ≥ 12 已投入，不另留一份完整備料圖示。
- spec_A：D 始終保留；2 ≤ t < 4 有傳輸副本；t ≥ 4 有 O 副本。
- report_A：t < 19 完全不存在；t ≥ 19 有 O 原件；19 ≤ t < 21 有傳輸副本；t ≥ 21 有 D 副本。
- release_A：t < 23 完全不存在；t ≥ 23 有 D 原件；23 ≤ t < 24.5 有傳輸副本；t ≥ 24.5 有 O 副本。
- service_OD 的關係線從 0 秒存在，工作狀態依序：
  - 0–5：待本批資料／資料確認；4–5 資料已收到，正在完成本例確認。
  - 5–11：待料／入料確認；10–11 已到料，正在完成本例入料確認。
  - 11–16：封裝中。
  - 16–19：測試中。
  - 19–31：封測工作完成。出貨尚未開始或尚未抵達，不會把已完成的測試改回未完成。
- 放行與出貨是另一個交付狀態：23 秒指示產生；24.5 秒 O 收到；25 秒出貨；27.5 秒到 C。
- 現場文件槽中可以保留多種文件，用短標籤區分；不可把規格槽的原件替換成報告而使資料無故消失。
- 所有動態存在條件由時間計算，不在每次重播時向陣列 append 圖形。
- 無隨機性，無需數值求解。只有路徑插值及明確狀態切換。

### G4 實作順序

1. 確認程式基礎與工具實際可用；沒有既有原始碼就建立最小可執行專案。
2. 先完成 4.5、6、10.5、17.5、22、26、29 秒的正確靜態狀態。
3. 串成完整 32 秒粗動畫，優先看清三類差異及去向。
4. 加入控制、說明、手機布局、減少動態與重設。

### H3 修正次序

先修正科學或產業語義誤導，再修流程缺漏、操作失效、裁切與接縫、追蹤困難，最後才調細節美觀。

依觀眾困惑對應修正：
- 分不出服務與報告：先修 P2 的固定關係方向與 P4–P5 的廠內工作；不要加服務運輸小球。
